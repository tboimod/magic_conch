# 방·사용 횟수 기반 RNG와 검증

실제 답변 선택기를 `keyed` 방식으로 변경했습니다. 같은 버전·확률 설정에서 **같은 런, 같은 방, 같은 사용 횟수이면 같은 답변**입니다. 방에서 기다린 시간이나 다른 방에서의 호출 순서는 답변에 영향을 주지 않습니다. 문구 ID를 정렬해 게임 재시작이나 언어 변경으로 선택 순서가 바뀌지 않게 했습니다. 한국어/영어는 같은 ID의 번역을 표시합니다.

시드 기반 의사난수 생성기(PRNG)도 RNG입니다. 시드와 알고리즘을 알면 재현·예측할 수 있는 성질과, 방 사이에 단순한 반복 패턴이 생기는 문제는 별개입니다.

## 실제 적용한 방식

- 런 시드, 층, 층 종류, 차원, 방 번호, 방 목록 ID, 생성/장식 시드, 사용 횟수를 각각 순서대로 섞습니다. `방 번호 + 사용 횟수`처럼 단순히 더하지 않습니다.
- [SplitMix64의 공개 혼합 함수](https://prng.di.unimi.it/splitmix64.c)를 바탕으로 문맥 키를 만들고, 답변 유형과 문구를 서로 다른 값으로 구분해 추첨합니다. 문맥 키 조합은 이 모드의 구현입니다.
- 나머지 연산의 편향을 피하는 거절 추출을 사용합니다. 40/20/40뿐 아니라 7/3/7 같은 가중치도 지원합니다. 잘못된 가중치나 합계 0은 기본 40/20/40으로 처리합니다. 비교 테스트는 잘못된 현재 설정을 건너뛰며, 올바른 기본 테스트 설정은 계속 실행합니다.
- 가변 RNG 상태를 보관하지 않아 저장 시점이나 호출 순서에 따라 결과가 밀리지 않습니다. 게임의 다른 RNG도 소비하지 않습니다.
- 단축키와 외부 API 모두 **성공한 활성화만 정확히 한 번** 사용 횟수를 증가시키고 즉시 저장합니다. 거절된 입력과 미리보기는 횟수를 소비하지 않습니다. API에도 방별 사용 제한을 적용합니다.
- 방 재방문·층 이동·이어하기에서 사용 횟수를 보존합니다. 새 런은 초기화합니다. 기존 저장 형식의 횟수도 새 방 키로 옮깁니다.

알고리즘이 바뀌었으므로 이전 버전과 같은 시드라도 답변은 달라질 수 있습니다. 기존에 사용한 횟수는 유지합니다. 같은 답변이 연속으로 나오는 것은 허용하며, 반복 금지나 강제 할당으로 확률을 조작하지 않습니다.

## 게임 콘솔 명령

모드를 다시 불러온 뒤 런에 들어가 실행합니다.

```text
mc test
mc test 10000 5 12345
mc test rooms
mc test rooms 1000 12345
mc predict 10
mc watch
mc stats
mc watch off
mc stop
```

| 명령 | 내용 |
| --- | --- |
| `mc test [회당 표본 수] [반복 횟수] [시작 시드]` | 기본 10,000회 × 서로 다른 5개 시드 × 11개 설정 × 3개 방식, 총 165만 회. 이어서 방 입장 검사 약 308만 회. `ALL_DONE`이 전체 완료입니다. |
| `mc test rooms [시드 개수] [시작 시드]` | 방 입장 검사만 실행합니다. 기본 1,000개, 허용 10~5,000개 시드. 현재 확률/강제 답변 설정을 복사합니다. |
| `mc predict [개수]` | 현재 방의 다음 답변들을 사용 횟수 순으로 미리 보여줍니다. `keyed`가 실제 적용 결과이며 횟수를 소비하지 않습니다. |
| `mc watch` / `mc stats` | 실제 성공한 사용의 관측 시작 / 집계 출력. 설정, 입장 후 프레임, 첫 방문/재방문, 사용 횟수, 방 종류, 층, 단축키/API별로 나눕니다. |
| `mc watch off` / `mc stop` | 관측 종료 / 진행 중인 합성 테스트 중단. |

`legacy`는 이전 수식, `rng`/`rng_sum`은 별도 Isaac RNG 객체, `keyed`는 현재 실제 선택기입니다. Isaac 비교 스트림은 `(런 시드 + 방 번호)`를 32비트로 정규화하고 0이면 1로 바꾸어 shift 35로 초기화합니다. 따라서 RNG 객체를 쓰더라도 이 비교용 시드 구성에는 층/차원 구분이 없습니다. RNG 알고리즘과 문맥 구성 모두 중요합니다.

콘솔을 열어 둔 상태에서도 렌더 콜백으로 나눠 실행합니다. 테스트는 실제 아이템 활성화, 방 이동, 사용 횟수 증가, 외부 모드 콜백을 실행하지 않습니다. 설정과 언어는 시작할 때 복사합니다. 관측은 명시적으로 `mc watch`를 입력할 때만 켜집니다.

출력은 콘솔 및 `Documents/My Games/Binding of Isaac Repentance+/log.txt`에 남습니다. 일반 Repentance는 `Binding of Isaac Repentance/log.txt`입니다. 표식은 `[MC RNG TEST]`, `[MC ROOM TEST]`, `[MC RNG WATCH]`이며, 방별 상세 집계는 로그에만 출력합니다.

## 방 입장 검사 범위

- 32비트 범위에 걸친 1,000개 시드 × 169개 가상 좌표 × 첫·둘째·셋째 사용.
- 방 번호, 격자 행/열, 층, 시드 끝자리별 첫 답변과 유형 내 문구 빈도.
- 가로/세로 이웃의 첫 답변과 같은 방 첫→둘째 답변의 조건부 빈도.
- 오른쪽 방 첫 답변과 왼쪽 방 둘째 답변의 일치율.
- 같은 좌표에서 층·층 종류·차원을 바꿨을 때의 일치율.
- 연속 숫자 시드, 음수 특수 방 번호, 입장 후 0/1/10/30/60/300/1800 프레임에 대한 선택 결과 불변성.
- 현재 층의 실제 RoomDescriptor 목록에서 가상 첫 사용을 별도로 기록합니다. 이 블록은 `legacy`, `rng_sum`, 방 `SpawnSeed`를 쓰는 `rng_spawn`, `keyed`를 비교합니다.

가상 격자는 실제 던전 생성이나 플레이어 이동 경로를 재현하지 않습니다. 격자 검사에서는 방 번호를 바꾸고 방 생성/장식 시드 등은 0으로 고정해 단순한 입력에서도 패턴이 생기는지 봅니다. 현재 한 층의 실제 목록은 작은 별도 표본이며, 장기적인 실제 플레이 경향은 `mc watch`로 관측합니다. 시간 검사는 선택 함수만 검사하며 스팸 방지로 입력이 거절되는 경우와 구분합니다.

`TOTAL`은 첫 사용을 한 번씩 셉니다. 조건별 `STRATUM`/`CONDITIONAL`을 다시 합산하면 중복됩니다. 강제 답변 설정에서는 해당 유형 100%가 정상입니다.

```text
python tests/aggregate_room_log.py "C:\Users\rudgh\Documents\My Games\Binding of Isaac Repentance+\log.txt"
```

최신 방 입장 블록이 완료됐을 때만 `tests/results/room-entry/`에 로그 발췌, JSON 정수 집계, CSV를 저장합니다. 중단된 최신 블록을 과거 완료 결과로 대체하지 않습니다.

## 이전 버전의 실제 게임 로그와 문제

보존한 [2026-10-10 게임 로그](../tests/results/isaac-2026-10-10.log)는 Repentance+ 1.9.7.12 / REPENTOGON 1.1.3에서 **변경 전** 두 방식, 총 110만 회를 비교한 자료입니다. 시드 4263037529, 좌표 84, 사용 횟수 0에서 시작했습니다.

기본 50,000회에서 이전 수식은 40/20/40%, Isaac RNG는 39.908/19.924/40.168%였습니다. 하지만 7/3/7에서는 이전 수식이 부정 100%, Isaac RNG는 41.204/17.694/41.102%였습니다. 이전 수식 `(값 × 17 + 11) % 17`이 항상 11이 되기 때문입니다.

이전 수식의 전체 유형 주기는 100회, 문구까지 포함한 주기는 200회입니다. [이전 수식의 200개 시드 잔여류 분석](../tests/results/legacy-room-entry.json)에서는 왼쪽 방이 긍정일 때 오른쪽 방이 부정일 확률이 0%, 위쪽 방이 중립일 때 아래쪽 방이 부정일 확률이 100%였습니다. 전체 비율이 정확해도 조건부 패턴은 심할 수 있습니다.

또한 이전 API 호출은 방 사용 횟수를 증가시키지 않아 동일 조건의 답변이 반복될 수 있었습니다. 이번 변경은 이 경로도 수정합니다.
